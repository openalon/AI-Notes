## 一句话

这份地图不是完整索引，只列与本书论点直接相关的主文件。作用是说明分析依据来自哪些文件，而不是承诺提供这些文件的正文。仅保留必要的工程性引用、模块定位和结构分析，不附源码副本。

## 核心概念

### 第 1 章 为什么需要 Harness Engineering

- `src/constants/prompts.ts`
- `src/utils/systemPrompt.ts`
- `src/query.ts`
- `src/services/tools/toolOrchestration.ts`
- `src/tools/BashTool/prompt.ts`

论点：prompt 属于控制面；query loop 才是骨架；工具和 Bash 风险说明 harness 的必要性。

### 第 2 章 Prompt 是控制面

- `src/constants/prompts.ts`
- `src/utils/systemPrompt.ts`
- `src/utils/claudemd.ts`
- `src/memdir/memdir.ts`
- `src/constants/systemPromptSections.ts`
- `src/main.tsx`

论点：system prompt 分层拼装；CLAUDE.md 与 memory 作为控制面输入；动态系统提醒与上下文注入。

### 第 3 章 Query Loop

- `src/query.ts`
- `src/QueryEngine.ts`

论点：query loop 的状态机性质；输入治理先于模型调用；流式事件消费与恢复分支；QueryEngine 对 conversation lifecycle 的所有权。

### 第 4 章 工具、权限与中断

- `src/services/tools/toolOrchestration.ts`
- `src/services/tools/toolExecution.ts`
- `src/services/tools/StreamingToolExecutor.ts`
- `src/hooks/useCanUseTool.tsx`
- `src/utils/permissions/PermissionResult.ts`
- `src/tools/BashTool/prompt.ts`
- `src/tools/BashTool/bashPermissions.ts`

论点：并发安全与上下文顺序回放；工具执行包裹层；allow / deny / ask；streaming 中断与 synthetic result；Bash 特殊高压治理。

### 第 5 章 上下文治理

- `src/utils/claudemd.ts`
- `src/memdir/memdir.ts`
- `src/services/SessionMemory/prompts.ts`
- `src/services/compact/autoCompact.ts`
- `src/services/compact/compact.ts`
- `src/query.ts`

论点：CLAUDE.md 分层发现和加载；MEMORY.md 作为入口索引；session memory 结构化连续性；autocompact 阈值 / buffer / circuit breaker；compact 后的工作语义重建。

### 第 6 章 错误与恢复

- `src/query.ts`
- `src/services/compact/autoCompact.ts`
- `src/services/compact/compact.ts`
- `src/services/api/withRetry.ts`

论点：withheld recoverable errors；PTL 的 collapse drain 与 reactive compact；max_output_tokens 的 escalate 与 resume；autocompact failure 熔断；compaction 自身 PTL 重试。

### 第 7 章 多代理与验证

- `src/utils/forkedAgent.ts`
- `src/coordinator/coordinatorMode.ts`
- `src/tasks/LocalAgentTask/LocalAgentTask.tsx`
- `src/utils/hooks/hooksConfigManager.ts`
- `src/skills/bundled/verify.ts`
- `src/memdir/memoryTypes.ts`

论点：forked agent 的 cache-safe 参数与状态隔离；coordinator 的 synthesis 责任；verification 独立成阶段；subagent lifecycle hook；task cleanup 与父子 abort 传播；对 stale memory 的 verify discipline。

### 第 8 章 团队落地

- `src/utils/claudemd.ts`
- `src/tools/SkillTool/prompt.ts`
- `src/tools/SkillTool/SkillTool.ts`
- `src/utils/forkedAgent.ts`
- `src/utils/hooks/hooksConfigManager.ts`
- `src/main.tsx`

论点：团队 CLAUDE.md 的分层稳定性；skill 作为制度切片而非 prompt 收藏夹；approval 边界与 allow rules；hook 生命周期治理；session startup 与 instructions / skill loading。

### 第 9 章 十条原则

并非从单一文件推出，是对前面所有章节的压缩。依据是这些核心模块共同呈现出的系统结构：prompt assembly、query loop、tool orchestration、permission model、context governance、recovery system、multi-agent orchestration、team governance hooks。

## 关键洞察

要对照源码，按章去这些文件，而不是从仓库根目录漫游。函数名和路径会随版本变；原则不会——这正是全书第二件事想保住的东西。

## 个人思考

若本地有 Claude Code 源码树，这份地图就是跳转表。没有源码也不妨碍用原则；有源码时用它验证「书是不是在瞎说」。
