## 一句话

**先有能过关的 agent 和一把尺子，再谈省钱。** 评测要能便宜地反复跑；成本看的是 **pass rate × 单次任务美元**，不是 token 单价。换小模型是清单最后一项，因为它直接削智能天花板。

## 核心概念

### Eval 四件套，打分方式决定你能不能常跑

`misc/building_evals.ipynb`：输入（常是模板变量）→ 模型输出 → golden → 分数。出题是一次性固定成本；**打分是每次重跑都要付的成本**，所以设计时就该偏向可自动打分。

| 方式 | 何时用 | 代价 |
|---|---|---|
| 代码（精确匹配 / 正则 / 包含） | 能把任务收成闭集或强制格式 | 最快最稳 |
| 人 | 几乎任何开放任务 | 慢、贵，尽量别依赖 |
| 模型 grader | 语气、开放 QA 等曾经要人的活 | 要抽检 grader 本身 |

经验：任务尽量做成可自动评（改选择题是常见手法）；grader 好不好只能试；**宁可题多质量一般，不要题少但每题雕花**——分布要贴近真实。Claude 可以帮你出题，但 golden 仍要人盯。

`misc/generate_test_cases.ipynb`：从带 `{{var}}` 的模板抽变量，让模型编合成值。有黄金例子就喂进去；可改模型自己的 planning 再 prefill（例如「文档用编号行」）。一半战场是逼真输入，另一半是 golden 输出——后者可让模型先写你再改。prompt cache 让多-shot 变便宜，这才是往 prompt 里堆例子的时机。

`tool_evaluation/tool_evaluation.ipynb`：多个 agent 独立跑同一份评测文件里的任务，盯的是 **工具有没有被正确调用**，不是最终散文好不好听。第 3 章的计算器在这里才算被验收。

### 官方深搜分数是 harness，不是模型玄学

`evals/agentic_search/reproduce_agentic_search_benchmarks.ipynb`：DeepSearchQA / BrowseComp 的公开分 **可以在 Messages API 上复现**。第三方测低，常见原因是 harness 配置——短对话无所谓的参数，30+ 工具、几十万 token 时会变成扣分项。

现场 cell 只跑 3 道演示题（数美元、数分钟）；全量 900 题是几百美元 + 数小时。杠杆按 notebook 顺序：

1. **PTC**：`code_execution` 为唯一 direct 工具，`web_search` / `web_fetch` 从代码里调，`response_inclusion: "excluded"`，页面身体不进对话。一道题 50+ fetch 时这是最大效率差。
2. **Compaction 指令**：默认摘要不知道基准里「原题 + 答案格式」必须活下来。不写 custom instructions，压完后模型会请你重述问题 → 零分。低 trigger 时效应最大。
3. `thinking: adaptive`、effort、budget：和第 4、9 章同一组旋钮。

模型卡：DeepSearchQA 常 **不开** compaction（1M 窗够用）；BrowseComp 用 3M budget **开** compaction。notebook 用后者的配置，好让 compaction 真的发生。

数据集：BrowseComp 1266（OpenAI）；DeepSearchQA 900（Kaggle）。harness 期望 `problem` / `answer` / `answer_type`。

### 成本：Applied AI 的清单，模型选择在最后

`cost_optimization/cost_optimization.ipynb` 把风尚从 tokenmaxxing 改成 budgetmaxxing：**不要靠降级模型或砍用例**，改周围架构，走到智能–成本 Pareto。整本约 $40 API，不必从头跑。

清单顺序：

1. 先在强模型上跑通，做 eval，记基线
2. Prompt cache
3. 输入：让模型用工具发现上下文，而不是 12k 手册整本塞 system
4. Agent 环：别让多轮历史线性膨胀（compact / 清工具 / PTC）
5. 收紧输出约束
6. 非交互走 Batch
7. **最后**才选更便宜的模型和 effort

度量是 `usage` → 美元。**看 cost per task 不看 cost per token**：贵模型若回合少，可能更便宜。案例：Acme 车险理赔 agent，system 里嵌 ~12k underwriting 手册，8 个调查工具 + 4 个终局 verdict。基线 Opus `effort=high`、无 cache、无上下文管理：**10/10，~$0.29/任务**。百万件索赔，每省 1 分钱 ≈ 年省 $1 万。质量条近 100%——标错比推理费贵，所以优化时不准掉点。

`finetuning/finetuning_on_bedrock.ipynb`：Bedrock 上微调 Haiku，JSONL `system` + `messages`。这是成本杠杆之一，**不是默认路径**。先 harness 再权重。

对照 recipe：

| 路径 | 钉的是什么 |
|---|---|
| `misc/building_evals.ipynb` | 评测本身要设计，打分必须可重复 |
| `misc/generate_test_cases.ipynb` | 合成数据填模板，仍要人过眼 |
| `tool_evaluation/tool_evaluation.ipynb` | 评的是工具有没有被正确调用 |
| `evals/agentic_search/reproduce_agentic_search_benchmarks.ipynb` | 官方分数在 Messages API 上怎么复现 |
| `cost_optimization/cost_optimization.ipynb` | 同一任务扫配置，找 Pareto，不找最聪明 |
| `finetuning/finetuning_on_bedrock.ipynb` | 微调是成本杠杆之一，不是默认路径 |

## 关键洞察

没有评测的第 5、8、9 章都只是演示。好评测的特征是：**能在每次改 prompt / 换模型 / 开 cache 时自动跑**，并且同时报质量和美元。DeepSearch 那份把第 3、4 章的 PTC 和 compaction 从「省钱技巧」升级成「分数的一部分」——harness 就是产品。

成本清单把「换 Haiku」放最后，是因为那是唯一直接砍天花板的杠杆。前面六项（cache、工具发现、压历史、收输出、batch）回收的是 **没有换来质量的美元**。

## 个人思考

第 1 章分类从 70% 到 95% 已经是评测驱动；本章把同一纪律扩到 agent 和账单。下一章是运行时看见这些数字：Admin API、session 封顶、地理钉扎。评测是实验室；可观测是值班。
