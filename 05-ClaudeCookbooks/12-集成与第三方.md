## 一句话

**第三方是适配器，证明边界，不规定默认栈。** 向量库、索引框架、百科、计算引擎、语音，接的都是第 2、3、6 章已经钉死的口：检索、工具、模态进出。2024 年的 LangChain / LlamaIndex 示例尤其不能当成今天的标准答案。

## 核心概念

### 向量库：嵌入 → 索引 → 检索 → 生成

`Pinecone/rag_using_pinecone.ipynb`：Voyage 嵌 Amazon 商品描述 → Pinecone（voyage-2，1024 维）→ 自然语言问。优化不是换库，是 **让 Claude 先把问题展开成一组检索关键词**（JSON 吐出），每词查 top-3 再合成。这是第 2 章「查询改写」的厂商皮肤。

`Pinecone/claude_3_rag_agent.ipynb`：LangChain v1 + Voyage + Pinecone，语料是预切的 arXiv。强调 Anthropic 吃 **XML agent**（`<tool>` / `<tool_input>`），不是典型 ReAct 文本。记忆不能把 `HumanMessage` 直接塞回去，要收成 `Human:` / `AI:` 字符串。版本写明是 LangChain v1 相对 0.0.3xx 的迁移——**读的是模式，不是抄依赖号**。

`MongoDB/rag_using_mongodb.ipynb`：另一套存储（Atlas vector index + Voyage），角色是 VC tech analyst，语料 Hacker Noon。机制相同：索引是检索后端，Claude 是生成器。

### LlamaIndex：索引框架里的工作流图

一组 notebook 把第 2、5 章的图用框架再画一遍：

| 路径 | 对应机制 |
|---|---|
| `Basic_RAG_With_LlamaIndex` | naive RAG |
| `Router_Query_Engine` | 第 5 章 routing |
| `SubQuestion_Query_Engine` | 拆子问题（轻量 orchestrator） |
| `ReAct_Agent` | 框架内的工具环；Anthropic 更吃 XML |
| `Multi_Document_Agents` | 多文档职责分区 |
| `Multi_Modal` | 第 6 章在框架里的入口 |

框架替你管的是 retriever 装配和 query engine 拓扑。不替你管：golden chunk 评测、cache、权限、session 预算。那些仍在第 2、4、10、11 章。

### 嵌入、百科、计算、语音

- `VoyageAI/how_to_create_embeddings.md`：嵌入模型另选。第 2 章 RAG / contextual 默认 Voyage，这里是说明书。换嵌入 = 换向量空间，索引要重建。
- `Wikipedia/wikipedia-search-cookbook.ipynb`：迭代搜百科——工具环 + 检索，不是一次 wiki dump。
- `WolframAlpha/using_llm_api.ipynb`：计算型工具。和第 3 章计算器同一原则：模型不算，引擎算。
- Deepgram / ElevenLabs：见第 6 章。STT/TTS 是进出适配器；延迟和账单在厂商侧，Claude 仍吃文本。

## 关键洞察

读这一章时盯接口，不盯 logo。能替换的是：向量库、嵌入、STT、TTS、索引框架。不能替换的是：输出契约、工具权限、上下文预算、评测和熔断。LangChain XML agent 那份甚至在提醒：**框架默认的 ReAct 字符串对 Claude 不是最优工具协议**。

厂商 notebook 会过期。Pinecone 维数、LangChain import、LlamaIndex query engine API 都会变。把「Voyage 1024 维 + 关键词展开」写进自己的系统时，要回到官方文档核对，不要冻结 cookbook 的 SDK 版本。

## 个人思考

12 章走完，依赖顺序是闭环的：第 1 章形状 → 2 检索 / 3 工具 / 4 预算 → 5 图 → 6 模态 / 7 技能 → 8 进程内循环 / 9 服务端循环 → 10 尺子 / 11 账单 → 12 把外部系统接到已经钉死的口上。跳到本章抄 LlamaIndex，等于从文件夹中间抽了一张卡片。
