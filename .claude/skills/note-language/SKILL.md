# 笔记用词

读者看到的是网页，不是制作笔记时的内部口径。入口页（首页、总览、专题首页、阅读导读、导读图、一句话）比章节正文更严：读者还没建立语境。

写或改笔记前读本文件。落盘路径仍走 `ingest-article` / `ingest-thought` / `ingest-book`。

## 为什么还要改

不专业通常不是错别字，而是下面五类把制作过程印到读者面上：

1. **内部动词当正文**：「打到」「停手」「落盘」「对照仓库」
2. **英文缩写当图上的词**：PTC、CMA、eval-opt、query loop、playtest loop、git ls、playtesters
3. **直译或修辞过猛**：cattle → 牲口；throwaway repo → 抛掷仓；body → 页面身体；离婚式离开反馈；开天之作
4. **本机真相**：`~/workspace2/...`、Perlego、对助手说的「再说一声」
5. **站点自己的词用错**：地图同时当入口、导读、源码索引；「骨架」同时当未读占位和运行时结构

贴进笔记的模板也算读者面。skill 里对助手说「先写骨架」可以；章节文件、专题首页、cite 芯片不要把「骨架」印出去。

源文引语和作者自己的概念不要改。Prompt 文里的「能量地图」、Martí 的 pets vs cattle，属于源文，不是我们的黑话。

## 站点自己的名字

| 层 | 用 | 不用 |
|---|---|---|
| 站点入口 | 总览（`00-Overview`） | 地图；总览卡片不要用地图 emoji |
| 一本书怎么读 | 阅读导读 | 阅读地图 |
| 源码去哪找 | 源码索引 | 源码地图 |
| 未读章 | 先占位 | 先骨架 / 已读（骨架） |
| 书或运行时怎么组织 | 结构 | 运行时骨架（读者面） |
| 顶栏书 | 书籍下拉 | 每加一本就往一级 nav 堆 |

## 入口页和图

分支标签、卡片文案、总览钩子、章节一句话：普通读者能看懂。代码标识符可以留英文。缩写第一次出现先写中文，再括英文。

已经改过、不要写回去：

| 不要写 | 写成 | 为什么 |
|---|---|---|
| 未打到 / 打到了 | 还没达到目标，回去改 / 达到目标，进入制作 | 试玩黑话，首页和导读图都出现过 |
| 再用原型和试玩打到它 | 把游戏改到符合这个目标 | 首页卡片 |
| clone 频率打到… | 推到… | 「打到」不是达到 |
| playtest loop / query loop（导读、一句话） | 试玩循环 / 主循环 | 循环名留给章节正文 |
| PTC / CMA / eval-opt / git ls（导读图） | 代码里调工具 / 托管 Agents / 评测再改 / 仓库里所有文件 | 图上第一次出现没有解释 |
| 对照仓库 `~/workspace2/...` | 官方 notebook 留在本机的 claude-cookbooks 仓库 | 网页不要本机绝对路径 |
| 机制片段来自对照仓库 | 机制片段摘自官方 notebook | 读者不知道「对照仓库」是什么 |
| 停手条件 | 可以进入下一步的标准 | 制作笔记时的内部词 |
| 同构 | 同一类判断 | 数学黑话 |
| 牲口 | 牲畜（对照 pets vs cattle） | 直译过猛；对照本身要留 |
| 抛掷仓 | 短命仓库 | throwaway 的生硬直译 |
| 页面身体 | 页面正文 | body 的直译 |
| demonstrably 改进 | 明确改进 | 夹在中文里的英文 |
| 自动捡仓库技能 | 自动发现仓库里的技能 | 太口语 |
| Perlego 墙截断 | 预览页截断 | 平台名对读者无意义 |
| 再说一声，我从…续 | 叠进 PDF 之后再续填 | 个人思考在跟助手说话 |
| 抢真相 | 否则笔记和官方仓库会各写一份，以后对不上 | 内部隐喻 |
| 出处在文末 | 出处在每篇标题下方 | cite 芯片早已改到标题下 |
| 一次想对 | 指望一次就做对 | 口语压缩过头 |
| 离婚式地离开反馈 | 彻底离开反馈 | 修辞过猛 |
| 开天之作 | 一锤定音的大文档 | 修辞过猛 |
| playtesters（未解释） | 试玩者 | 角色名先写中文 |
| 运行时骨架（入口页） | 运行时结构 | 「骨架」在读者面上已经脏了 |
| registry 不是全书 | 官方食谱表不是全书 | 内部文件名当读者词 |

章节一句话里不要直接甩 CMA / PTC。先写全称再括缩写，例如「托管 Agents（Claude Managed Agents，CMA）」「代码里调工具（Programmatic Tool Calling，PTC）」。

Book 1 正文里的 `query loop`、Cookbooks 章节里的 `PTC` / `CMA`，第一次出现带解释之后可以当术语用。不要为了「全中文」把代码标识符也译掉。

## 不要改的

- 源文固有名词和作者自己的概念（能量地图）
- 原文引语（You have to treat repositories as pets, not cattle.）
- 未读章里的「（阅读后填写）」——那是状态，不是黑话
- skill / eval 内部工作词（落盘、骨架、wikilink）：读者看不到

## 修笔记时回写本文件

用户纠正用词、图上的标签、直译、本机路径，且已经落盘、以后还会再犯：把可执行的那条写进**本文件**的表，不要再分别贴进三个整理 skill。文章 / 思考 / 书籍各自的落盘流程（YAML、cite、目录）仍写回对应 skill。
